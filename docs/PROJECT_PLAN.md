# خطة مشروع نظام إدارة سنتر تعليمي

## 1. فكرة المشروع

المشروع عبارة عن نظام ويب لإدارة سنتر تعليمي.

النظام يتيح للطلاب:

- إنشاء حساب وتسجيل الدخول.
- استعراض المدرسين.
- استعراض المواد الدراسية.
- تقديم طلب حجز مع مدرس معين.
- متابعة حالة الحجز.
- استقبال الإشعارات.

كما يتيح للإدارة:

- إدارة المدرسين.
- إدارة المواد.
- إدارة الطلاب.
- إدارة طلبات الحجز.
- إدارة الإعلانات والمحتوى.
- إرسال الإشعارات.
- متابعة الإحصائيات.

ملاحظة مهمة: لا يوجد حسابات خاصة بالمدرسين. كل بيانات المدرسين تدار من خلال لوحة تحكم الأدمن فقط.

---

## 2. أنواع المستخدمين

### Admin

مدير النظام، وله صلاحية الوصول إلى لوحة التحكم وإدارة كل محتوى النظام.

### Student

الطالب، وله صلاحية إنشاء حساب، تصفح المدرسين والمواد، إرسال طلب حجز، واستقبال الإشعارات.

---

## 3. وظائف الطالب

### الحساب

- إنشاء حساب جديد.
- تسجيل الدخول.
- استعادة كلمة المرور.
- تعديل البيانات الشخصية.

### تصفح الموقع

- عرض الصفحة الرئيسية.
- عرض كل المدرسين.
- عرض تفاصيل مدرس.
- عرض كل المواد.
- عرض تفاصيل مادة.
- البحث عن مدرس أو مادة.

### الحجز

- اختيار مادة.
- اختيار مدرس.
- إرسال طلب حجز.
- إضافة ملاحظات اختيارية.
- متابعة حالة الطلب.

حالات الحجز:

- قيد المراجعة.
- مقبول.
- مرفوض.
- ملغي، اختيارية لاحقا.

### الإشعارات

الطالب يمكن أن يستقبل إشعارات مثل:

- قبول الحجز.
- رفض الحجز.
- إعلان جديد.
- رسالة من الإدارة.
- تغيير موعد مدرس.

- الصفحة الرئيسية.
- جميع المدرسين.
- تفاصيل المدرس.
- جميع المواد.
- تفاصيل المادة.
- من نحن.
- لماذا تختارنا.
- آراء الطلاب.
- الأسئلة الشائعة.
- تواصل معنا.
- تسجيل الدخول.
- إنشاء حساب.

---

## 5. الصفحة الرئيسية

تحتوي على الأقسام التالية:

- نبذة عن السنتر.
- لماذا تختارنا.
- المميزات.
- المواد الدراسية.
- المدرسين.
- آراء الطلاب.
- أحدث الأخبار أو الإعلانات.
- تواصل معنا.

---

## 6. نظام المدرسين

كل مدرس يحتوي على:

- الاسم.
- الصورة.
- نبذة مختصرة.
- المادة التي يدرسها.
- سنوات الخبرة.
- المؤهلات.
- عدد الحصص الأسبوعية.
- جدول المواعيد.

مثال للمواعيد:

```txt
السبت: 6:00 مساء
الاثنين: 5:00 مساء
الخميس: 7:00 مساء
```

---

## 7. نظام المواد

كل مادة تحتوي على:

- اسم المادة.
- وصف مختصر.
- المدرسين الذين يشرحونها.
- الصفوف الدراسية الخاصة بها.

---

## 8. نظام الحجز

الطالب يقدم طلب حجز مع مدرس معين.

بيانات الطلب:

- اسم الطالب.
- رقم الهاتف.
- الصف الدراسي.
- المادة.
- المدرس.
- ملاحظات اختيارية.

بعد إرسال الطلب:

- يصبح الطلب في حالة قيد المراجعة.
- يظهر الطلب داخل لوحة تحكم الإدارة.
- يتلقى الأدمن إشعارا بوجود طلب جديد.
- يستطيع الأدمن قبول أو رفض الطلب.
- عند القبول يصل إشعار للطالب.
- عند الرفض يصل إشعار للطالب مع سبب الرفض، إن وجد.

---

## 9. لوحة تحكم الإدارة

### Dashboard

تعرض:

- عدد الطلاب.
- عدد المدرسين.
- عدد المواد.
- عدد الحجوزات الجديدة.
- عدد الحجوزات المقبولة.
- عدد الحجوزات المرفوضة.
- أحدث طلبات الحجز.
- عدد الزيارات، اختيارية.

### إدارة المدرسين

- إضافة مدرس.
- تعديل بيانات مدرس.
- حذف مدرس.
- رفع صورة.
- كتابة نبذة.
- تحديد المادة.
- تحديد أيام ومواعيد الحصص.

### إدارة المواد

- إضافة مادة.
- تعديل مادة.
- حذف مادة.
- ربط المادة بالمدرسين.
- تحديد الصفوف الدراسية الخاصة بالمادة.

### إدارة الحجوزات

- عرض جميع الطلبات.
- البحث داخل الطلبات.
- فلترة حسب الحالة.
- قبول الطلب.
- رفض الطلب.
- كتابة سبب الرفض.
- تغيير حالة الطلب.

### إدارة الطلاب

- عرض جميع الطلاب.
- البحث عن طالب.
- تعديل بيانات طالب.
- إيقاف حساب طالب.
- حذف حساب طالب.

### إدارة آراء الطلاب

- إضافة رأي.
- تعديل رأي.
- حذف رأي.
- التحكم في ظهور الرأي داخل الصفحة الرئيسية.

### إدارة صفحات الموقع

- من نحن.
- لماذا تختارنا.
- تواصل معنا.
- الأسئلة الشائعة.
- سياسة الخصوصية.
- الشروط والأحكام.

### إدارة الإعلانات

- إضافة إعلان.
- تعديل إعلان.
- حذف إعلان.
- عرض الإعلان في الصفحة الرئيسية.
- إرسال الإعلان كإشعار للطلاب لاحقا.

### رسائل التواصل

- استقبال رسائل صفحة تواصل معنا.
- عرض بيانات المرسل.
- تغيير حالة الرسالة إلى مقروءة.
- الرد على الرسالة لاحقا، إن احتجنا.

## 10. الإشعارات

الإشعارات يمكن تنفيذها باستخدام Firebase Cloud Messaging.

أنواع الإرسال:

- إرسال لطالب واحد.
- إرسال لمجموعة طلاب.
- إرسال لجميع الطلاب.

أمثلة على المجموعات:

- جميع الطلاب.
- طلاب مادة معينة.
- طلاب صف معين.

يفضل الاحتفاظ بسجل للإشعارات المرسلة لمعرفة:

- عنوان الإشعار.
- محتوى الإشعار.
- المستلم.
- تاريخ الإرسال.
- حالة الوصول، إن أمكن.

---

## 11. النظام الإداري والأمان

النظام يجب أن يدعم:

- حماية صفحات الأدمن.
- منع الطلاب من دخول لوحة التحكم.
- التحقق من تسجيل الدخول.
- إدارة الجلسات.
- تسجيل العمليات المهمة.

أمثلة على Activity Logs:

```txt
Admin added teacher
Admin updated subject
Admin accepted booking
Admin rejected booking
Admin sent notification
```

- عرض المدرسين.
- عرض المواد.

- صفحة تفاصيل مادة.

## 15. مراحل التنفيذ

### المرحلة الأولى: تجهيز المشروع

- مراجعة هيكل المشروع الحالي.
- تجهيز نظام التصميم الأساسي.
- تجهيز صفحات Layout العامة.
- تجهيز Layout لوحة التحكم.
- تجهيز الاتصال مع Supabase.
- إعداد Authentication.

### المرحلة الثانية: الصفحات العامة

- بناء الصفحة الرئيسية.
- بناء صفحة المدرسين.
- بناء صفحة تفاصيل المدرس.
- بناء صفحة المواد.
- بناء صفحة تفاصيل المادة.
- بناء صفحة تواصل معنا.

### المرحلة الثالثة: لوحة تحكم الأدمن

- بناء Dashboard.
- بناء إدارة المدرسين.
- بناء إدارة المواد.
- بناء إدارة الحجوزات.
- بناء إدارة الطلاب.

### المرحلة الرابعة: نظام الحجز

- بناء Form طلب الحجز.
- حفظ الطلب في قاعدة البيانات.
- عرض الطلبات للأدمن.
- قبول أو رفض الطلب.
- عرض حالة الطلب للطالب.

### المرحلة الخامسة: المحتوى والإعدادات

- إدارة آراء الطلاب.
- إدارة الإعلانات.
- إدارة صفحات الموقع.
- إعدادات الموقع العامة.
- رسائل تواصل معنا.

### المرحلة السادسة: الإشعارات والتحسينات

- ربط Firebase Cloud Messaging.
- حفظ Device Token.
- إرسال إشعار عند قبول أو رفض الحجز.
- إرسال إعلان كإشعار.
- إضافة سجل الإشعارات.
- تحسين SEO.
- تحسين الأداء.
- دعم الوضع الليلي، إن كان مطلوبا.

## 16. ترتيب عملي للمبتدئ

ابدأ بهذا الترتيب:

1. افهم الصفحات المطلوبة.
2. ابن الواجهة ببيانات وهمية.
3. ابن لوحة التحكم ببيانات وهمية.
4. جهز Supabase والجداول.
5. اربط المدرسين والمواد بقاعدة البيانات.
6. اربط نظام الحجز.
7. أضف تسجيل الدخول والصلاحيات.
8. اختبر كل Feature وحدها.
9. بعد الاستقرار أضف الإشعارات والتحسينات.

القاعدة المهمة: لا تبدأ بأصعب جزء. ابدأ بما يظهر للعميل بسرعة، ثم اربطه بالبيانات تدريجيا.
